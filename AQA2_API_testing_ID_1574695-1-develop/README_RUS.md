## Глава 3

### 3.1. Что такое API

Слово «API» мелькает в вакансиях даже для начинающих тестировщиков. То REST API, то SOAP API, то просто API. Что же это за зверь такой? Давай разбираться!

«А зачем это мне? Я ведь web тестирую! Вот если пойду в автоматизацию, тогда да… Ну, еще это в enterprise тестируют, я слышал…» —  скажешь ты. 

А вот и нет! Про API полезно знать любому тестировщику. Потому что API — это то, как системы взаимодействуют между собой. И это взаимодействие ты можешь видеть каждый день даже на самых простых и захудалых сайтах.

API — это программный интерфейс, который описывает, как одна компьютерная программа взаимодействует с другими программами (в противоположность пользовательскому интерфейсу, который используется для взаимодействия программы с конечным пользователем). Обычно API входит в описание интернет-протокола (например, SCI), программного каркаса (фреймворк) или стандарта вызовов функций операционной системы. Часто реализуется отдельной программной библиотекой или сервисом операционной системы. API используют программисты при написании всевозможных приложений.

API упрощает процесс программирования при создании приложений. Он абстрагирует базовую реализацию и предоставляет только необходимые разработчику объекты или действия. 

Например, если графический интерфейс для почтового клиента может предоставить пользователю кнопку, которая выбирает и выделяет новые письма, то API для ввода/вывода файлов может дать разработчику функцию, копирующую файл из одного места в другое. Разработчику при этом не нужно понимать операции файловой системы, которые происходят за кулисами.

Проще говоря, API — это способ взаимодействия программного кода с другими программными компонентами. То есть API позволяет одной компьютерной программе (например, боту или сайту) использовать функции другой программы.

Как инженер по автоматизации тестирования ты всегда будешь тестировать API — на любом проекте в том или ином виде. Далее рассмотрим самые востребованные инструменты на рынке, которые помогут тебе в этом процессе.

### 3.2. OkHttp

Когда стоит задача по проверке сетевых взаимодействий в приложениях, то универсальный инструмент — **OkHttp**. OkHttp — это библиотека с открытым исходным кодом, которая работает как HTTP-клиент для Java и Kotlin.

OkHttp позволяет легко отправлять HTTP-запросы и проверять ответы от сервера и предлагает интуитивно понятный API.

Она поддерживает современные протоколы, включая HTTP/1.1 и HTTP/2, а также все основные HTTP-методы (GET, POST, PUT, DELETE и другие).

Библиотека хорошо справляется с обработкой сразу нескольких запросов и предоставляет дополнительные функции: кеширование запросов/ответов, пул соединений для оптимизации подключений, аутентификацию и др.

#### Настройка клиента и запроса для подготовки среды, в которой будут выполняться и обрабатываться запросы для тестирования API

Класс `OkHttpClient` — клиент для отправки HTTP-запросов и обработки ответов.

`OkHttpClient.Builder` — класс для настройки клиента под свои требования: настройка кеша, аутентификации, добавления перехватчиков, установки тайм-аутов и др. Когда настройка завершена, вызывается метод `build()`, который возвращает экземпляр класса `OkHttpClient`.

**Совет по более эффективному использованию OkHttp**: создай один экземпляр `OkHttpClient` и используй его для всех запросов. У каждого клиента есть свой пул соединений и потоков. Повторное использование этих пулов снижает задержки и экономит ресурсы памяти. А создание клиентов для каждого запроса — это трата ресурсов, т. к. пулы соединений и потоков останутся неиспользованными.

#### Отправка запроса

Метод `newCall` в классе `OkHttpClient` используется для подготовки запроса к выполнению в будущем. Принимает объект `Request` и возвращает объект `Call`.

Класс `Call` — это запрос, готовый к выполнению. Этот запрос можно отменить, и его нельзя выполнить более одного раза, т. к. экземпляр класса представляет одну пару запрос/ответ. Запрос можно выполнить двумя методами:

- `execute()` — для синхронного выполнения запроса. Этот метод сразу же запускает запрос и блокирует текущий поток до тех пор, пока не будет получен ответ или не произойдет ошибка;
- `enqueue()` — для асинхронного выполнения запроса. Метод планирует запрос на будущее, и диспетчер решает, когда его выполнить. После выполнения клиент получает ответ или информацию об ошибке.

#### Чтение ответа для проверки, насколько API корректно работает и возвращает ожидаемые данные

HTTP-ответ представлен классом `Response`. Тело ответа можно прочитать только один раз, а затем оно становится недоступным. Остальные свойства ответа неизменяемы.

Чтобы проверить, насколько успешно прошел запрос к серверу, используется метод `isSuccessful()` класса `Response`. Метод проверяет код состояния (status code) HTTP-ответа.

Если код находится в диапазоне 200–300, то запрос успешен (значение true).

Все, что за пределами этого диапазона, указывает на неуспех запроса (метод возвращает значение false).

### 3.3. REST

Что такое REST?

**REST (Representational State Transfer)** — это набор принципов и правил, определяющих, как компоненты распределенных систем должны обмениваться данными между собой. Если говорить проще, это «каркас», состоящий из архитектурных правил, который помогает проектировать приложения так, чтобы их легко можно было масштабировать и адаптировать под новые задачи.

Если функциональность, которую создает разработчик, соответствует принципам REST, то ее называют **RESTful**.

### 3.4. REST Assured
REST Assured — это инструмент для тестирования API, который интегрируется в Java-тесты. Посмотри на базовую его использования:

```
given()
    .when()
    .get(someEndpoint)
    .then()
    .statusCode(200)
    .body();
```

Ключевые слова given, when и then формируют сценарий запроса:

- given задает параметры запроса (заголовки, тело, авторизацию);
- when указывает HTTP-метод и эндпоинт для обращения;
- then описывает проверки ответа (статус, структуру данных, заголовки).

Дополнительно можно преобразовать тело ответа в объекты `JsonPath` или `XmlPath` для последующего анализа данных.

В реальных сценариях тесты сложнее: добавляются заголовки, авторизация, тело запроса и другие параметры.

_Практический совет_: если API не имеет множества уникальных ресурсов с особыми требованиями, то для упрощения работы в код можно добавить хелперы или общие классы — например, шаблоны для повторяющихся запросов или отдельные методы для валидации ответов.

### 3.5. Retrofit

**Retrofit** — это REST-клиент для Java и Android, который упрощает отправку и получение структурированных данных (например, JSON или XML) через веб-сервисы.

Ключевая особенность Retrofit — гибкость: ты можешь выбрать конвертер для сериализации данных (стандартно используется Gson для JSON, но можно подключить кастомные решения для XML или других форматов).

Для выполнения HTTP-запросов Retrofit задействует библиотеку OkHttp. 

Для написания автотестов с помощью Retrofit тебе понадобятся как минимум три класса:

- сервисный класс — здесь объявляются методы для взаимодействия с API (эндпоинты, параметры запросов);
- базовый класс клиента — настраивает Retrofit (URL, конвертеры, таймауты);
- тестовый класс — реализует сценарии проверки API (вызов методов, валидация ответов).

Архитектура приложений на Retrofit может варьироваться, но техническая основа остается неизменной. В рамках текущего проекта мы сосредоточимся на минимальной, но функциональной реализации — этого будет более чем достаточно, чтобы понять принципы работы фреймворка тестирования API, которые едины для любых архитектурных решений.
